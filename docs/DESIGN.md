# Jarvis：用可视化动作回答问题的医学内容智能体（设计方案）

> 状态：评审稿 v0.1 · 2026-09-29
> 首个样例：`HOPE_案例1.pptx`（一例复发难治多发性骨髓瘤病例诊治分享，32 页）

---

## 0. 一句话目标

把一份医学 PPT 转成一个**可以被遥控的交互式网站**。用户用自然语言提问后，AI agent 不只是输出文字，而是**像播放一段微型幻灯片那样，操作网站上的真实组件**：定位、聚光、绘制图表、对比影像、逐步解说，用这种方式回答问题。

## 1. 需求决策记录

| # | 问题 | 决定 |
|---|---|---|
| 1 | 用什么大模型 | 云端 Claude API |

| 3 | 语音 | 第一版只做文字，预留语音接口 |
| 4 | 问题超出 PPT 范围时 | **严格只答 PPT 内容**：没有就明确说没有，并定位到最接近的内容 |
| 5 | 网站形态 | 重构成"病例看板"，每条内容都能溯源到原 PPT 的页码 |
| 6 | 是否复用 | 要，做成可复用的流水线，后续还有案例 2、3…… |
| 7 | 复杂问题怎么展示 | 多步导览 |
| 8 | PPT 中的笔误 | 列出清单，由人工确认 |

| 10 | 回答形式 | **每个问题都尽量用"一段动作序列"来回答**，而不是跳到一个静态页面；网站本身要有丰富的 HTML 动画（不渲染成视频） |

## 2. 总体架构

```
┌──────────────────── 离线准备（可以花很长时间）────────────────────┐
│ PPT ─① 抽取→ raw/slides.json + media/ + slides/*.png                    │
│     ─② 结构化→ case.json（通用内容核心 + 领域视图）                    │
│     ─③ 校验→ validate.py（覆盖率审计）+ review.md（人工确认）          │
│     ─④ 影像理解→ 热点、描述                                             │
│     ─⑤ 建索引→ anchors.json（锚点目录）+ 实体/同义词表 + 时间索引      │
│     ─⑥ 预编导览→ tours.json（问题库 → 动作序列），人工挑选、修改       │
└──────────────────────────────────────────────────────────────────┘
                                   │
┌──────────────────── 运行时（要快）────────────────────────────────┐
│  浏览器：看板 UI  ←  舞台引擎（Stage）  ←  动作执行器（校验锚点）    │
│        ▲ 对话框                               ▲ 流式动作 (SSE)      │
│        └──── 提问 ────▶ 本地 Node 后端 ──▶ 快速路径：命中预编导览    │
│                                        └─▶ 慢速路径：Claude 实时编排  │
└──────────────────────────────────────────────────────────────────┘
```

核心原则：**agent 只输出"指令"，不输出页面**。页面上能做什么，由组件库和动作协议共同决定。这样速度快、结果可预测，而且每个动作都能校验。

## 3. 内容模型：通用核心 + 领域视图

**问：这个方案是不是只适合这一份病例 PPT？** 不是。系统分成三层，只有最上面一层与内容类型有关：

| 层 | 内容 | 是否与 PPT 类型相关 |
|---|---|---|
| **动作协议 + 舞台引擎 + agent** | 聚光、镜头、绘制、对比、解说……只认"锚点"和"块类型" | **无关**，所有 PPT 共用 |
| **通用内容核心**（Core） | 块类型：文本段落、要点列表、表格（到单元格）、数据序列/图表（到数据点）、图片 + 热点、KPI 数字、流程/步骤、引用文献、术语表；每个块都有 `id` 和 `src` | **无关**，任何 PPT 都能抽取成这些块 |
| **领域视图**（Lens） | 把块组织成更适合该类内容的可视化和导航 | **相关**，按 PPT 类型选用或新增 |

计划的领域视图：

| Lens | 适用 PPT | 主要组件 |
|---|---|---|
| `case-course` 病程 | 病例汇报（本例） | 治疗时间轴、阶段色带、指标趋势、影像前后对比、分子演变 |
| `trial` 临床研究 | 研究解读（本例第 23–29 页就属于这种） | 研究设计流程图、基线特征表、缓解率堆叠图、K-M 曲线 + 风险人数、泳道图 |
| `review` 专题综述 | 疾病综述、专家讲座 | 主题树/思维导图、证据对比矩阵（研究 × 终点）、机制示意图（分步动画）、指南推荐分级卡片 |
| `guideline` 指南 | 诊疗指南解读 | 诊疗决策流程图（可以点亮路径）、推荐等级表、新旧版本对比 |
| `generic` 兜底 | 任何 PPT | 按原幻灯片顺序排列的块流 + 自动生成的章节目录 |

所以，新的 PPT 类型**不需要新框架**：流水线先把内容抽成通用块（这一步总能完成），如果有合适的 Lens 就套用，没有就用 `generic`。等某类 PPT 出现得足够多，再为它新增一个 Lens（新增的是组件和 schema 扩展，协议和 agent 都不用改）。

> 本例的 `case.json` 目前按 `case-course` + `trial` 两个 Lens 手工组织。P2 会把它拆成 `core`（块）+ `lens`（视图）两部分，让结构符合上面的分层。

## 5. 索引：怎样让 agent 定位得既准又快

### 5.1 锚点目录（Anchor Catalog）：索引的最小单位是"一个数值"

页面上每个可以被指向的东西都有全局唯一的 id，同时也是 DOM 锚点（`data-anchor="…"`）。粒度分为四级：

```
section   sec.trends                       整个模块
block     series.mprotein                  一张图 / 一张表 / 一个事件卡片
item      tbl.baseline_mm.sflc             表格的一行 / 时间轴上的一个事件
value     series.mprotein.2024-05-08       一个数据点 / 一个单元格 / 影像上的一个热点
```

构建时，为每个锚点生成一条目录记录：

```json
{
  "id": "series.mprotein.2024-05-08",
  "type": "data_point",
  "text": "2024-05-08 M蛋白 10.6412 g/L（髓外进展评估，KD 巩固期间）",
  "parent": "series.mprotein", "section": "sec.trends",
  "date": "2024-05-08", "phase": "ph.kd",
  "entities": ["M蛋白", "IgG-λ"], "emphasis": true,
  "related": ["ev.emd1_eval", "img.emd1_ct"],
  "actions": ["spotlight", "chartFocus", "callout"],
  "src": [10]
}
```

`actions` 声明这个锚点支持哪些可视化动作，agent 只能在这个范围内选择。

### 5.2 另外三类辅助索引

| 索引 | 作用 | 例子 |
|---|---|---|
| **实体/同义词表** | 把用户的说法映射到锚点 | "埃纳妥 / 埃纳妥单抗 / elranatamab"、"兆珂速 / 达雷妥尤单抗 / 抗CD38"、"M蛋白 / M峰 / SPEP"、"CAR-T / 细胞治疗"。PPT 自带的术语表会先收进来；由模型补充的同义词**只用于检索，不作为回答内容** |
| **时间索引** | 处理"移植后三个月怎样""2024 年发生了什么""CAR-T 前后对比"这类问题 | 日期 → 事件、数据点、影像；阶段 → 时间区间 |
| **关系图** | 回答"为什么"时顺着关系找证据 | 事件 → 相关表格、影像、数据点（`links`）；数据点 → 所属事件 |

### 5.3 运行时怎么检索

- **单个病例：不需要向量检索。** 本例 `case.json` 约 64KB，精简成锚点目录后大约 2–3 万 token，可以**整份放进系统提示词，并开启 prompt caching**。这样模型能"看到"全部内容，直接引用锚点 id，精度最高；有缓存时首 token 延迟低，费用也低。
- **内容很多时**（多案例、上百页的综述）：先做**混合检索**（BM25 关键词 + 向量 + 实体匹配，并按时间过滤），取出 top-k 的块及其上下级，再交给模型。
- **强约束**：模型输出的每个锚点都要经过校验，锚点不存在就拒绝并要求重试；回答中的每一句结论都必须附上 `cite: [anchor…]`，没有引用的句子不会显示。

### 5.4 如何衡量"准"

`eval/questions.jsonl`：每道题标注"必须指向的锚点"和"不应该出现的内容"。用 Playwright 自动跑 agent，统计：锚点命中率、精确率、首个动作延迟、PPT 外问题的拒答正确率。

## 6. 回答 = 一段"微型幻灯片"（舞台模式）

### 6.1 为什么不是"跳到某一页"

网页内容多，用户关心的往往只是几个数字或一张图。因此回答不是滚动到某个位置，而是进入**舞台模式（Stage）**：

1. 看板整体后退：变暗、轻微模糊、缩小到 96%；
2. 相关组件被"请"到舞台中央（FLIP 动画，是原组件本身，不是截图）；
3. 按步骤播放；每一步由**镜头 + 动作 + 解说**组成；
4. 结束后，用户可以"钉住"这一段结果，或者一键回到看板中对应的位置。

### 6.2 如何突出重点（聚光灯）

| 手段 | 效果 |
|---|---|
| **Spotlight** | 用 SVG 遮罩在目标周围挖出一个圆角"光洞"，其余区域压暗；光洞可以在多个目标之间平滑移动 |
| **放大镜 / 镜头推近** | 把表格中的某个单元格、图表上的某个点放大 1.5–3 倍 |
| **数值跳动** | 关键数字从 0 滚动到目标值（count-up），同时显示单位和"来自第 N 页" |
| **引线标注** | 从目标拉出一条引线，连到一句简短解说 |
| **对比高亮** | 两个值并排显示，中间用箭头标出变化幅度（例如 λ 87.82 → 1.33 mg/L，↓98%） |
| **原文红字** | PPT 里标红的内容（已抽取为 `emphasis`）默认带一层微光提示 |

### 6.3 组件自带的动画原语（组件库需要实现）

- **时间轴**：游标扫过一段时间；阶段色带依次点亮；事件卡片弹出
- **趋势图**：折线按时间逐段绘制；某个点脉冲闪烁；参考线或阈值线滑入；对数和线性坐标之间变形
- **表格**：某一行闪亮；某个单元格放大；两列之间差异着色
- **影像**：热点圈画出（描边动画）；前后两张图用滑块对比；局部放大
- **分子演变**：两个时间点的 VAF 条形变形过渡（IGLL5 27.3% → 68.1% → 80.9%）
- **文献图表**：堆叠柱逐段生长；K-M 曲线按时间揭开；风险人数表同步高亮
- **机制示意图**（`review` Lens）：分步构建的 SVG 图（例如双抗桥接 T 细胞与 BCMA）

### 6.4 导览脚本（Tour）格式

```json
{
  "question": "这个病人为什么会反复髓外复发？",
  "steps": [
    { "camera": "sec.pathology",
      "do": [{"spotlight": "mol.fish.1q21"}, {"morph": "mol.fish.1q21", "from": "2023-06", "to": "2026-01"}],
      "say": "高危遗传学：1q21 扩增从初诊时的 8% 升到 2026 年的 90%（4 个拷贝）。",
      "cite": ["tbl.baseline_labs.fish", "tbl.fish_2026.1q21"] },
    { "camera": "sec.timeline",
      "do": [{"timelineSweep": ["2024-05", "2026-01"]}, {"pulse": ["ev.emd1_eval", "ev.emd2_breast", "ev.emd3"]}],
      "say": "髓外病灶三次出现：右肩胛区（2024.05）→ 左乳和右髂骨（2025.09）→ 皮下及腹股沟（2026.01）。",
      "cite": ["ev.emd1_eval", "ev.emd2_breast", "ev.emd3"] },
    { "camera": "img.emd1_ct",
      "do": [{"drawHotspot": "img.emd1_ct.h1"}, {"callout": ["img.emd1_ct.h1", "SUVmax 9.39，76×54mm"]}],
      "say": "第一次髓外进展时，右肩胛骨后方出现肌肉肿块。",
      "cite": ["img.emd1_ct.h1"] },
    { "camera": "tbl.ihc_2026",
      "do": [{"spotlight": "tbl.ihc_2026.ki67"}, {"spotlight": "path.2026_arm.dx"}],
      "say": "2026 年病理为母细胞样浆细胞瘤，Ki-67 约 90%。",
      "cite": ["tbl.ihc_2026.ki67", "path.2026_arm.dx"] },
    { "camera": "sum.case", "do": [{"spotlight": "sum.case.f2"}],
      "say": "病例总结中列出的高危因素：1q21 扩增、FGFR3/IgH 重排、母细胞样形态、多次髓外浸润。",
      "cite": ["sum.case.f2"] }
  ]
}
```

注意：解说词只**复述 PPT 中已有的信息及其组合**，不加入 PPT 以外的机制解释（决策 #4）。PPT 如果没有给出因果结论，agent 只展示相关证据，并注明"PPT 未给出因果结论"。

### 6.5 界面布局

```
┌────────────┬──────────────────────────────────────────────┐
│ 推荐问题   │                                              │
│ ① ……      │          看板 / 舞台（主区域）                │
│ ② ……      │                                              │
│ ③ ……      │                                              │
│ ④ ……      │                                              │
│ ⑤ ……      ├──────────────────────────────────────────────┤
│            │ [ 对话输入框                        ] [发送] │
│ 章节导航   ├──────────────────────────────────────────────┤
│ · 概览     │ ▼ Agent 过程（默认展开，可折叠）              │
│ · 时间轴…  │  12:01:03.120  路由    命中预编导览 T3 (0.92)│
│            │  12:01:03.180  步骤1   spotlight mol.fish…   │
└────────────┴──────────────────────────────────────────────┘
```

**左侧：Top 5 推荐问题**
- 离线准备：人工挑出 5 个最有价值的问题，每个都配一段**人工审核过的预编导览**。点击后直接播放，不经过模型，演示效果最稳定。
- 选题原则：5 个问题合起来能覆盖网站的主要能力（时间轴、趋势图、影像、分子、文献），并且每个都能完全用 PPT 内容回答。
- 每个导览绑定 `content_version`：数据被修改后，导览会被标记为待重审，左侧显示提示。
- 下方是章节导航，可以手动浏览。

**底部：Agent 过程面板**（默认展开，可折叠，便于理解工作机制和排查问题）
- 按时间顺序实时显示整个处理管线，每行带时间戳和耗时：
  1. **路由**：是否命中预编导览、匹配到哪一个、相似度多少；
  2. **检索**：用到了哪些锚点或事实（可以点击，舞台会定位过去）；
  3. **回答计划**：结论 → 依据的事实 id → 推导方式 → 不确定性；
  4. **校验**：通过或拒绝的项和原因（例如"不兼容比较：CXCR4 与 FDG 的 SUVmax"、"引用了未审核的修正值"），以及重试；
  5. **动作执行**：每一步的 `step_id`、动作、执行状态（排队 / 播放中 / 完成 / 取消）；
  6. **指标**：首个动作延迟、总耗时、token 数和缓存命中情况（API 模式下）。
- 模型"思考"部分的显示原则：只显示**结构化的回答计划**和模型返回的思考摘要（前提是提供方返回了这些内容），不伪造推理过程。
- 每条记录都可以展开查看原始 JSON。整次回答可以导出为 trace 文件，用于回放和提交问题报告。
- 对外演示时隐藏系统提示词全文和本机路径等信息，只显示业务层的事件。
- 过程面板和舞台共用同一个事件流（`answer_id` / `step_id`），两边的状态始终一致。

### 6.6 动作协议（完整清单）

| 类别 | 动作 |
|---|---|
| 镜头 | `camera(anchor)`、`zoom(anchor, k)`、`stage.enter/exit`、`pin()` |
| 聚焦 | `spotlight(anchor[])`、`pulse(anchor[])`、`callout(anchor, text)`、`dimOthers()` |
| 时间 | `timelineSeek(date)`、`timelineSweep(from, to)`、`phaseHighlight(phase)` |
| 图表 | `chartFocus(series[], range)`、`chartDraw(series)`、`pointPulse(point)`、`compare(pointA, pointB)`、`scale(log/linear)` |
| 表格 | `rowFlash(row)`、`cellZoom(cell)`、`diff(tableA, tableB)` |
| 影像 | `imageOpen(img)`、`drawHotspot(h)`、`imageCompare(a, b)`、`magnify(h)` |
| 叙事 | `say(text, cite[])`、`step()`、`wait(ms)`、`countUp(anchor)` |
| 溯源 | `showSource(slide)`：显示原 PPT 这一页的截图 |

用户可以随时暂停、上一步、下一步、调整倍速或跳过。所有动作都是幂等的，而且可以打断。

## 7. Agent 运行时

| 路径 | 条件 | 做法 | 目标延迟 |
|---|---|---|---|
| **快速路径** | 问题和预编导览库匹配（向量 + 实体，由一个小模型判定是否等价） | 直接播放预编的 tour | < 0.5 s 开始播放 |
| **慢速路径** | 没有命中 | Claude（系统提示词 = 锚点目录 + 动作协议，已缓存）**流式输出 JSON 步骤**；第 1 步解析完成就立即开始播放，后续步骤边生成边入队 | 首个动作约 1–2 s |
| **追问** | "放大一点""换成对数坐标""回到上一张" | 基于当前舞台状态做增量操作 | < 1 s |

- 后端：本地 Node 服务，保存 API Key，向浏览器转发 SSE 流；
- 模型：主模型用 Claude，另配一个小模型做路由和匹配判定。具体型号在 P3 按实测延迟和准确率决定；
- 严格模式：系统提示词规定只能使用目录中的事实；答不上来时输出 `{"not_in_source": true, "nearest": [...]}`，舞台会展示最接近的内容，并说明"本病例资料未涉及"；
- 慢速路径生成的好答案可以一键"收藏为导览"，问题库会持续积累。

**模型提供方（可替换）**：后端通过 `ModelProvider` 接口调用模型，目前有两种实现：

| Provider | 用途 | 说明 |
|---|---|---|
| `claude-code`（当前） | 内部演示阶段 | 在 macmini-4 上以无头模式调用本机已登录的 Claude Code（`claude -p --output-format stream-json`），使用本人的 Claude 订阅。**只限本人操作的演示**：由本人提问，其他人旁观；公开链接必须设置访问码，不开放给他人自行提问。每次调用有进程启动开销，所以更依赖预编导览的快速路径 |
| `anthropic-api` | 对外试用 / 商用 | 使用 Console API Key，支持 prompt caching，延迟更低，可以多人并发 |

切换提供方只需改动后端的一个配置项，前端和动作协议不受影响。

## 8. 视觉设计：浅色、专业、酷

- **底色**：极浅的蓝灰（约 `#F6F8FB`），加一层很淡的点阵或网格纹理；卡片为白色，用轻微阴影和 1px 描边区分层次
- **主色**：深海军蓝（延续原 PPT 和医院 VI）；**强调色**为青蓝/电光青，用于聚光、数据高亮和光晕；**语义色**：缓解用青绿，进展用珊瑚红，治疗阶段用一组低饱和色带
- **"酷"主要来自动效，而不是花哨的装饰**：聚光灯遮罩、FLIP 组件飞入、折线描绘、数字滚动、热点描边、时间轴游标扫描、轻微的玻璃质感舞台层（backdrop-filter）
- **字体**：中文用 Noto Sans SC / HarmonyOS Sans；数字用等宽字体（tabular），保证数值对齐、滚动时不跳动
- **可访问性**：遵守 `prefers-reduced-motion`（动画降级为淡入淡出）；颜色之外同时使用形状或标记来区分含义
- 技术栈：React + Vite + TypeScript；ECharts（图表，自带动画和变形）；GSAP（时间线编排、MotionPath）；Framer Motion（组件级过渡、FLIP）；SVG mask 实现聚光灯
